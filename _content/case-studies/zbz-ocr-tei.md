# ZBZ OCR/TEI Pipeline

## Context and research question

The ZBZ OCR/TEI pipeline opens up the Jeanne Hersch papers held at the Zentralbibliothek Zürich. The task is to carry a multilingual corpus of mixed document types, monographs, journals and edited volumes, into validated TEI-XML following the DTA base format. In scale, tool integration and documentation density this is the most extensive case in the record.

## Data

The corpus consists of PDF scans in French, German, English and Italian; the repository holds the current extent. No Python script was written by hand or reviewed by the author. All code was generated by Claude Code against the knowledge base, tested and committed, which makes the case the record's strongest instance of the artefact as a functional by-product of the documents.

## Approach

The pipeline runs in stages from the source PDF through OCR, layout analysis with quality assurance, and named-entity linking to Wikidata and GND, on to TEI-XML generation and an inspection and correction viewer. A knowledge base with one document per pipeline stage configures the agent layer together with the action layer, and the knowledge base itself is curated through prompts rather than edited by hand.

An agent-based screening stage was part of the pipeline for a time and was abolished in May 2026 by a documented project decision, after no human had assigned the release states it recorded and the agent was certifying its own output.

## Methodological contribution

The defining feature is a full pipeline infrastructure with one verification interface per stage, concretely a viewer that renders the facsimile, the layout overlay and the OCR or TEI output side by side. The expert judgement thereby gets a defined place at every milestone, which interrupts the error cascade that characterises multi-stage automated pipelines. The knowledge base carries the domain in depth, one document per stage, and the artefacts that discriminate most finely in the record come from exactly this kind of depth.

## Limits

The repository is closed and waiting on the release of the partner institution. The verification front end is public, so the interfaces the case argues for can be inspected while the knowledge base behind them cannot.

The abolished screening stage is the sharpest finding of the case, and it is a negative one. An agent that records release states which no human assigns produces a provenance layer documenting nothing, and the arrangement certified its own output for as long as it ran. It went unnoticed because a stage that produces records reads as a check.

An oversized CLI reference in the action layer produced drift waves with every change to the pipeline, since each change invalidated a description that was carried a second time. Any action layer duplicating an interface instead of pointing at it inherits the problem.
