# Distillate: Diátaxis, a systematic framework for technical documentation authoring (Procida)

The documentation framework that divides technical documentation along the same axis the site's knowledge-action composition uses, action against cognition, and derives its four document types from that axis together with a second one. It supplies the citable name for the separation the site describes. Quotations come from the pages /start-here/ and /foundations/, whitespace normalised from the HTML rendering. Typographic quotation marks, apostrophes and dashes are normalised to their ASCII forms in the quotations.

## Core statements

- The framework holds that there are four kinds of documentation, each answering a different need and each written differently. ^s1
  > "The core idea of Diátaxis is that there are fundamentally four identifiable kinds of documentation, that respond to four different needs. The four kinds are: tutorials, how-to guides, reference and explanation. Each has a different purpose, and needs to be written in a different way." (procida-2024, /start-here/)
- The first axis is action against cognition, glossed as knowing how against knowing that. ^s2
  > "A skill or craft or practice contains both action (practical knowledge, knowing how, what we do) and cognition (theoretical knowledge, knowing that, what we think). The two are completely bound up with each other, but they are counterparts, wholly distinct from each other, two different aspects of the same thing." (procida-2024, /foundations/, §Action/cognition)
- The second axis is acquisition against application, being at study against being at work. ^s3
  > "the relationship of a practitioner with their practice is that it is something that needs to be both acquired, and applied." (procida-2024, /foundations/, §Acquisition/application)
- The two axes are claimed to define the territory completely, which is the argument for four types rather than three or five. ^s4
  > "This is why there are necessarily four quarters to it, and there could not be three, or five. It is not an arbitrary number." (procida-2024, /foundations/, §The map of the territory)
- Reference is defined as propositional knowledge that is explicitly not a guide to action. ^s5
  > "They contain propositional or theoretical knowledge, not guides to action." (procida-2024, /start-here/, §Reference)
- A how-to guide is defined by its addressee's situation, a real-world goal held by an already-competent user. ^s6
  > "A how-to guide addresses a real-world goal or problem, by providing practical directions to help the user who is in that situation. A how-to guide always addresses an already-competent user, who is expected to be able to use the guide to help them get their work done." (procida-2024, /start-here/, §How-to guides)
- The framework's justification is that documentation must serve the needs of its users, from which the four forms are derived rather than stipulated. ^s7
  > "Diátaxis is based on the principle that documentation must serve the needs of its users. Knowing how to do that means understanding what the needs of users are." (procida-2024, /foundations/, §Two dimensions of craft)

## Terms

- **Action and cognition**: the axis separating practical knowledge, knowing how, from theoretical knowledge, knowing that. [[20_distillates/publications/procida-2024-diataxis#^s2]]
- **Acquisition and application**: the axis separating the practitioner at study from the practitioner at work. [[20_distillates/publications/procida-2024-diataxis#^s3]]

## Open questions

- Every type in this framework is addressed to a human practitioner, and the second axis, study against work, presupposes a reader who acquires a skill over time. A model that loads a document at the start of a session does not acquire anything that persists, so the second axis has no counterpart in the machine-addressee case while the first one does.
- The framework separates documents so that a reader finds the one form they need. A knowledge base for an agent separates them so that a stable description is not overwritten by a volatile instruction, which is a different reason for the same cut, and the source does not carry it.
