# Exploration is taken up again inside an implementation milestone and forces an update of the data document.

## Statement

In the aggregation step of the recorded session the tool at first writes no scripts for the very numerous spreadsheets, and the author interrupts the run in the middle. His finding is that the exploration phase was not thorough enough, and his explicit order is to update the `data.md` and work the new knowledge back into it. The session needed that second pass over the `data.md` because of the number of documents. The re-entry happens after the document set already existed and while a milestone of the implementation plan is running, so the return goes into the phase the new knowledge belongs to rather than into the specification alone. The witness is the method's author on his own recorded practice.
