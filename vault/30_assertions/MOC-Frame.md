# MOC: Frame

Claims behind the paper's epistemic frame: exploration as research, the nature of humanities data, the translation problem, and the surrounding AI discourse (Vibe Coding, Spec-Driven Development, context engineering, model failure modes). Added with the bibliography-traceability sweep of 2026-07-23.

- [[30_assertions/fair-emphasises-machine-actionability-of-data]] — The FAIR principles place specific emphasis on machines' ability to find and use data, and extend to the tools and workflows that produced it
- [[30_assertions/making-source-data-machine-addressable-is-interpretive-modelling]] — Source data legible only as PDF layout becomes machine-addressable only through explicit markup, and the categorisation this requires is itself interpretive
- [[30_assertions/schoech-distinguishes-smart-and-big-data]] — Schöch separates smart data from big data along structure, cleanliness, and volume
- [[30_assertions/sarkar-vibe-coding-material-disengagement]] — The first empirical study of vibe coding describes it as an iterative goal-satisfaction cycle under selective human oversight
- [[30_assertions/humanities-data-is-constructed-not-given]] — Humanities data is a selectively constructed abstraction, not a given
- [[30_assertions/context-rot-nonuniform-degradation-with-length]] — LLM performance degrades non-uniformly as input length grows, even on simple tasks, with input length isolated as the cause
- [[30_assertions/search-cannot-represent-collection-abundance]] — The search box, the default interface to digital collections, is ungenerous and cannot represent their abundance
- [[30_assertions/generous-interfaces-reveal-collection-through-browsing]] — Generous interfaces reveal a collection's scale and complexity through rich, browsable representations
- [[30_assertions/humanities-data-are-capta-not-given]] — Humanities data are constructed capta, actively taken, rather than given data
- [[30_assertions/discarded-visualisations-retain-epistemic-value]] — Sandcastle visualisations are never failures; even when discarded they generate knowledge

- [[30_assertions/experimental-prototype-yields-knowledge-not-product]] — An experimental prototype produces generalised knowledge rather than a product
- [[30_assertions/sycophancy-agreement-over-truth]] — LLMs exhibit sycophancy, matching the user's stated beliefs over the truthful answer rather than challenging them

- [[30_assertions/visualisation-is-research-process-not-means]] — Visualisation in the humanities is a research process in its own right, not merely an instrument serving research
- [[30_assertions/vibe-coding-speed-quality-tradeoff]] — Empirical review finds vibe coding fast and accessible but perceived as unreliable, a speed-quality trade-off

- [[30_assertions/digital-history-collaboration-is-a-trading-zone]] — Collaboration between historians and computational experts is a trading zone
- [[30_assertions/owens-data-holds-evidentiary-value]] — Data is not itself evidence but a multifaceted object that can be mobilised as evidence
- [[30_assertions/sdd-frameworks-converge-on-specification-over-prompt]] — Across agentic software-development frameworks the isolated prompt loses centrality and persistent specification artifacts coordinate the agents
- [[30_assertions/rse-institutionalised-intermediary-profession]] — The Research Software Engineering movement institutionalised the domain-technical intermediary as a recognised profession
- [[30_assertions/fair-principles-findable-accessible-interoperable-reusable]] — The FAIR principles are a concise, measurable set for making data Findable, Accessible, Interoperable, and Reusable
