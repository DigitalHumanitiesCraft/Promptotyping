# Promptotyping Document

A Promptotyping Document is a knowledge document in project-bound form, one of the versioned Markdown files maintained in the `knowledge/` folder of a repository, where the git history holds the versions it passed through. One document carries one function, so a small tool repository may consolidate several functions into one file and a multi-stage pipeline may split them further. Section 3.3 carries the definition. The naming and the first grouping of these documents are the author's [[20_distillates/publications/pollin-2025d-promptotyping-blog#^s5]], and their standing as the actual artefact of the context engineering is stated in [[20_distillates/publications/pollin-2026b-lisa-positioning#^s3]].

The neighbouring genre is the data management plan. The research data community asks for machine-actionable DMPs that infrastructure can act on, while an agent implements from a Promptotyping Document in every session, and a document no agent can work from gets revised for exactly that reason (Section 3.3).
